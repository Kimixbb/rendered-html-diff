Rendered HTML Diff App Flow

This version uses Mermaid as the graph source so the app flow is easier to read, easier to maintain, and less dependent on hand-positioned SVG coordinates.

Build-Time Flow

flowchart LR
  before["before.html<br/>old static document"]
  after["after.html<br/>new static document"]
  cli["CLI<br/>parse args and read files"]
  sanitize["sanitizeHtml<br/>strip scripts and unsafe embeds"]
  payload["report template<br/>embed both documents as JSON"]
  output["diff.html<br/>portable standalone report"]

  before --> cli
  after --> cli
  cli --> sanitize --> payload --> output

  classDef file fill:#ddf4ff,stroke:#0969da,color:#24292f;

At build time, no browser work happens. The CLI creates one self-contained report that carries the sanitized old and new documents inside the file.

Browser Runtime Flow

flowchart TB
  load["Load diff.html<br/>read embedded JSON"]
  iframe["Render after.html<br/>inside sandboxed iframe"]
  oldDoc["Parse before.html<br/>off-screen DOM"]
  afterBlocks["Collect after blocks<br/>headings, p, li, pre, tr, graphic"]
  beforeBlocks["Collect before blocks<br/>same semantic model"]
  match{"Same identity?"}
  diff["Compute block diff<br/>added, modified, deleted"]
  inline["Render details<br/>words, lines, table cells"]
  overlay["Apply git-like colors<br/>green, yellow, red"]
  sidebar["Build side panel<br/>changed blocks only"]
  navClick["Click side item<br/>scroll to target"]

  load --> iframe --> afterBlocks --> match
  load --> oldDoc --> beforeBlocks --> match
  match --> diff --> inline --> overlay
  diff --> sidebar --> navClick --> overlay

  classDef browser fill:#fff8c5,stroke:#9a6700,color:#24292f;
  classDef model fill:#fbefff,stroke:#8250df,color:#24292f;
  classDef output fill:#dafbe1,stroke:#2da44e,color:#24292f;
  classDef decision fill:#ffffff,stroke:#57606a,color:#24292f;
  class load,iframe,oldDoc,overlay,navClick browser;
  class afterBlocks,beforeBlocks,diff,inline model;
  class sidebar output;
  class match decision;

At runtime, the new HTML is the visible surface. The old HTML is parsed beside it so the viewer can explain what changed without executing input scripts.

Block Identity Ladder

flowchart TB
  block["Rendered block"]
  key{"Has data-diff-key?"}
  section{"Inside keyed section?"}
  fingerprint["Fallback fingerprint<br/>tag + heading path + text"]
  stable["key:id<br/>most reliable"]
  local["section:id:index<br/>stable enough for simple reports"]
  weak["fallback:id<br/>last resort"]

  block --> key
  key -- yes --> stable
  key -- no --> section
  section -- yes --> local
  section -- no --> fingerprint --> weak

  classDef source fill:#ddf4ff,stroke:#0969da,color:#24292f;
  classDef decision fill:#ffffff,stroke:#57606a,color:#24292f;
  classDef good fill:#dafbe1,stroke:#2da44e,color:#24292f;
  classDef warning fill:#fff8c5,stroke:#9a6700,color:#24292f;
  class block source;
  class key,section decision;
  class stable,local good;
  class fingerprint,weak warning;
Identity source Why it matters
data-diff-key Best signal for agent-generated reports because the author controls it.
section local order Useful when children are stable but do not carry their own keys.
text fingerprint Useful as a last resort, but moves and rewrites can confuse it.

Why The Recent Bugs Happened

flowchart LR
  native["Viewer styles native nodes<br/>li, tr, pre"]
  drift["Layout breaks<br/>markers drift and cells collapse"]
  lists["List fix<br/>marker span + body span"]
  columns["Stable list columns<br/>1, 2, 3 align"]

  rows["Table row flattened<br/>invalid tr content"]
  cells["Cell-level diff<br/>keep td and th"]
  valid["Valid table layout<br/>highlight changed cells"]

  native --> drift --> lists --> columns
  rows --> cells --> valid

  classDef bug fill:#ffebe9,stroke:#cf222e,color:#24292f;
  classDef fix fill:#dafbe1,stroke:#2da44e,color:#24292f;
  class native,drift,rows bug;
  class lists,columns,cells,valid fix;

The viewer should add explainable overlays without changing the semantic shape of the rendered document. Lists and tables need special handling because their native layout rules are easy to disturb.
