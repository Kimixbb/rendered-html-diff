Rendered HTML Diff Viewer Debugging Report

An outside user opened the generated report and found that the visual diff was hard to read in lists, tables, and code snippets.

User Feedback

  1. The interface should use Git-style colors for added, modified, and deleted content.
  2. Some text appears outside the highlighted boxes when blocks contain inline code.
  3. A changed table row sometimes stops looking like a table row.
  4. Deleted list items are shown as red placeholder cards instead of real list items.
  5. Numbered list markers do not align after a deleted item is inserted.

Initial Investigation

  • The first CSS pass applied padding and pseudo markers directly to every changed element.
  • The table diff flattened a changed tr into text, which produced invalid table markup.
  • The list fix used list-style-position: inside only on highlighted items.

Problem Matrix

Area Observed Behavior Likely Cause
Tables Changed row text escaped its cells. The row renderer replaced the entire tr content.
Lists Deleted items had a large red card and no normal marker. The deleted item was rendered as a generic div.

Code Path Under Review

function createRemovedPlaceholder(block, doc) {
  const placeholder = doc.createElement("div");
  placeholder.className = "rhd-removed-block";
  placeholder.textContent = "Deleted " + readableKind(block.kind);
  return placeholder;
}

Next Debugging Steps

  1. Handle table rows without replacing the tr.
  2. Keep the red deleted placeholder for list items.
  3. Try moving list markers inside highlighted boxes.

Remaining Risk

The report may still look acceptable in the fixture while breaking for a user with inline code, changed tables, or deleted ordered-list items.
